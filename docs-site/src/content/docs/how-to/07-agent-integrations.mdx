## Skill first, MCP as the fallback

OMem ships one **skill** — a small, agent-neutral wrapper that teaches an agent when to query your work memory and how to walk the results. There are two ways an agent picks it up:

- **If your agent has a skill / plugin mechanism, use the skill.** It's the richer integration: the skill carries trigger semantics (when to auto-query) and the progressive-disclosure flow, not just raw tools. This is the preferred path for **Claude Code, Codex, and Claw Hub**.
- **If your agent only speaks MCP, use the `omem mcp` server.** Same six tools, but as a generic MCP endpoint — the fallback for agents without a native skill mechanism (Cursor, Cline, Continue, Zed, …).

Both surface the **same six read-only capabilities**; the difference is whether the agent also gets the skill's trigger + drill guidance.

## Recommended: one command for every agent

The fastest way to install the skill — into *all* your agents at once — is the cross-agent [`skills`](https://skills.sh) CLI:

```bash
npx skills add seacen/omem --global
```

It clones the OMem repo, finds the skill, detects which agents you have installed (Claude Code, Codex, Cursor, Cline, Windsurf, Gemini CLI, …), and drops the skill — `SKILL.md` plus its `references/` — into each agent's skills directory. `--global` installs it user-wide; omit it to install only into the current project. Useful flags:

- `-a '*'` / `--agent '*'` — install to every detected agent without prompting (`-y` skips the confirmation entirely).
- `--copy` — copy files instead of the default symlink (use if your agents don't follow symlinks).
- `npx skills list` / `update` / `remove omem` — inspect, refresh, or uninstall, across all agents at once.

That's the whole integration for any agent the `skills` CLI supports. The per-agent sections below are for installing through an agent's *own* plugin system instead — same skill, useful when you'd rather not use the `skills` CLI or your agent isn't in its detection list.

## Per-agent install (alternative to `npx skills`)

### Claude Code

With the `omem` CLI installed and set up, add the marketplace and install the skill:

```
/plugin marketplace add seacen/omem
/plugin install omem@omem-marketplace
```

The agent now auto-invokes OMem on work-context questions. Verify by asking *"check my OMem health"* — it should run `omem doctor`.

### Codex

OMem ships a Codex plugin that carries the same skill. With the `omem` CLI installed, install it from Codex's plugin browser:

1. In Codex, run `/plugins` to open the plugin browser.
2. Add OMem's source: `seacen/omem` (the GitHub repo). Use the marketplace tabs to switch to it.
3. Open the **OMem** plugin and choose **Install plugin**.

That's all — the plugin brings OMem's skill with it, so Codex now auto-queries your work memory the same way Claude Code does. Verify by asking *"check my OMem health"* — it should run `omem doctor`.

<Aside type="note" title="Codex's plugin browser is interactive">
Codex installs third-party plugins through the interactive `/plugins` browser rather than a one-line command — you add the `seacen/omem` source and pick OMem from the list. The plugin carries the same skill content as the Claude Code one.
</Aside>

### Claw Hub (OpenClaw)

OMem's skill is published on **Claw Hub**, OpenClaw's public skill registry. With the `omem` CLI installed, install the skill by its slug:

```bash
openclaw skills install omem
```

(Add `--global` to install it for every workspace.) You can also browse or search it at [clawhub.ai](https://clawhub.ai), or use the standalone Claw Hub CLI:

```bash
npm i -g clawhub
clawhub install omem
```

<Aside type="note" title="One skill, three front doors">
Claude Code, Codex, and Claw Hub all reach the *same* skill content — identical triggers, identical six tools. You're not configuring three different things; you're installing one skill through whichever door your agent uses.
</Aside>

## Agents without a skill — the MCP server

`omem mcp` runs a stdio MCP server exposing the six tools to any MCP client. One config entry connects it:

**Cursor** — `.cursor/mcp.json` (or Settings → MCP Servers):
```json
{
  "mcpServers": {
    "omem": { "command": "omem", "args": ["mcp"] }
  }
}
```

**Cline, Continue, Zed** — same shape (`command: "omem"`, `args: ["mcp"]`) in that agent's MCP config file.

<Aside type="tip" title="When to use MCP if your agent also has a skill">
If your agent supports a skill, prefer it — you get the trigger and drill guidance for free. Reach for the raw MCP entry only when the agent has no skill mechanism, or when you specifically want to wire the tools yourself.
</Aside>

## The six tools (skill = MCP)

Both surfaces expose exactly these, and nothing else:

| Tool | What it does |
|---|---|
| `query` | Ranked search across all indexed work |
| `page_get` | Full wiki page (frontmatter + body) |
| `raw_get_path` | Path to the original source file (file kind) |
| `raw_get_parsed_path` | Path to the parsed source (with version history) |
| `wiki_ls` | Browse pages by kind / source / account / date |
| `doctor` | OMem health check |

<Aside type="note" title="Read-only by design">
Setup, ingest, re-indexing, purging, config changes — none are exposed to agents, on either surface. They stay deliberate human actions, so connecting an agent can never let it reconfigure or delete your data. See [querying from an agent](/concepts/07-querying-from-an-agent/).
</Aside>

## Prerequisite (all paths)

Every integration needs the `omem` CLI installed and configured first:

```bash
curl -fsSL https://github.com/seacen/omem/releases/latest/download/install.sh | sh
omem setup
omem ingest
```

See [install](/getting-started/01-install/) and [setup](/getting-started/02-setup-wizard/).
