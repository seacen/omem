## 为什么是这件事，由这个人来做

我在 **Unilever** 做 IT 管理，身处一家大型跨国企业真实运转的第一线——也身处它真实落地 AI 的第一线。OMem 之所以存在，根子就在这个位置上。

在大企业里，你会同时看清两件大多数 AI 工具都没看到的事。其一，痛点到底在哪：真正要紧的工作从不待在某个规整的系统里，它散落在收件箱、共享盘、PPT、表格、会议纪要、扫描版 PDF 之间。其二，企业 AI 为什么总是卡住：今年这批真正能干活的 agent 是有本事的，可它们看不见这些上下文，于是日常用起来，总觉得"差那么一口气"。

这道缝隙，我不是站在 PPT 前指点它——我就在里面干活。这段时间我一直在真实、要紧的工作里身先士卒地用 AI：准备给高层看的材料、把那些过去要熬夜的活自动化掉、做一些能让 AI 在真实业务里真正顶用、而不只是 demo 好看的工具。**OMem 就是其中之一**——是我用业余时间、一个晚上接一个晚上写出来的，因为我得先自己用上它，才敢拿去请别人用。

这也是这里每一个设计取舍背后的视角：本地优先，因为真实工作数据敏感、不该还要去走 IT 工单；agent 中立，因为最火的 agent 年年在换，但你的工作上下文不该跟着换；中文一等公民，因为我每天泡着的工作本就是双语的。这些都不是在抽象里挑出来的功能——而是一线真正需要的东西。
